Perceptual Grade User Manual

English简体中文

Blender 感知调色

Perceptual Grade 是用于 Blender 着色器和合成器节点编辑器的三阶段色彩变换。 当前 Next 实现提供 Linear、Tone 与 Color 控件、共享调色、节点自有 动画调色、调色栈和受管理的图像烘焙。技术报告 介绍模型及当前实现约定。

旧版 Blender 下载Perceptual Grade 1.23.2 · 2026-11-01 · 并非 Next

上方 ZIP 仅为保留的 1.23.2 扩展，供旧版用户使用，其中不包含 Perceptual Grade Next。本手册目前尚未提供 Next 扩展 ZIP。

请从安装与节点连接开始，再按三个阶段调色 操作。在 Linear 中处理场景工作空间下的白平衡和颜色关系，在 Tone 中 设置影调锚点，在 Color 中调整明度、彩度、Adaptance 和六点 Warp 色网。共享 调色可供多个节点复用；若节点需要独立动画，可转换为节点自有设置。调色栈则把 按顺序排列的正向条目合并为一次采样变换。

本手册介绍 Blender 着色器和合成器节点。参考章节 讲解数学模型；Next 策略章节记录运行时发布、 故障处理和烘焙行为。

模型和实现参考见致谢，许可信息见许可证。

安装与连接

Blender 扩展

旧版开发 ZIP包含 Perceptual Grade 1.23.2，并非本手册介绍的 Next 产品。手册网站不提供 Next 扩展 ZIP。获得 Next 安装包后，请通过 Blender 的扩展偏好设置安装。

在着色器或合成器编辑器中选择 添加 → 颜色 → Grade 或 Grade Stack。 选中节点后，打开编辑器 N 面板中的 Perceptual Grade 侧栏。选中的 Grade 输出会显示 Linear 和 Tone 控件；Color 控件分为 J、C、Adaptance 和 Warp 面板。 编辑共享控件前，请在节点选择器中指定已有 Grade，或使用 新建调色 创建一个。

在着色器中连接材质

将 Image Texture 的 Color 输出连接到 Grade 的 Color 输入。把 Grade 输出连接到 需要调整的材质输入，例如 Principled BSDF 的 Base Color，并保持着色器连接到 Material Output。若要预览不受照明影响的图像，可把 Grade 输出连接到 Emission 着色器。

Image Texture 的 Color Space 应与源图像编码一致，以便 Blender 正确解码。整个节点 图使用场景当前支持的工作色彩空间；Next 支持 Linear Rec.709、Linear Rec.2020 和 ACEScg 场景空间。

在合成器中连接图像

在合成器中启用 Use Nodes。将 Image 或 Render Layers 的 Image 输出连接到 Grade Color，再把处理结果连接到后续操作或输出。添加 Viewer 分支，以便编辑时 检查结果。采样 Render Layers 前先渲染一次。

若要制作节点自有动画，请右键 Grade 节点并选择 转换为节点自有调色。这会将 当前设置复制到该节点。共享 Grade 和栈条目仍由数据块持有；详见共享与复用调色。

分三个阶段调色

Grade 由三个相连的阶段组成：Linear 设置曝光、白平衡和整体色彩关系； Tone 将场景亮度映射到感知明度；Color 按影调与色相调整明度和彩度。 建议按此顺序操作，并在每个阶段后检查完整图像。

先选择中性参考，并确保输入图像已正确解码。在 Linear 中校正偏色并设置整体 亮度，不要把高光一律推到白色。在 Tone 中，根据图像动态范围放置黑、阴影、 中间调、白和高光锚点。在 Color 中进行选择性调整，同时观察肤色、中性色和 高彩度颜色。单个 Grade 是全局变换，无法补偿局部光照或错误的输入色彩配置。

Next 在侧栏中提供完整的 Stage 3 数值控件。J 按低／高彩度及对立色方向 调整明度响应。C 使用相同驱动因素调整彩度响应，并提供全局彩度增益。 Adaptance 为 Shadows、Midtones、White 和 Highlights 设置对立色空间目标， 并共享半影响彩度。Warp 在四个非黑色调锚点上使用六点循环色网：彩度以档为 单位，相位显示存储的角度偏移，Scale 也以档为单位。各类控件会在影调间平滑 插值。目前没有可拖动的 Warp 图示，请使用数值字段。

数值模型使用冻结的 Tone 后选择器及带符号能量。执行顺序为 J/C 响应、Warp 色相与彩度并选择正 Scale、选择性 Adaptance、H–K 修复，最后将 Scale 应用于 修复后的对立色坐标，并将 Scale 的平方应用于能量。H–K 守护在 Scale 之前执行。若需要，RGB 输出边界 会另行把结果投影到受支持的 RGB 色域内。

比较调色版本时，保持曝光、视图变换和输入解码方式一致。场景线性值可以高于 显示白；应通过预期的显示变换判断，而不是截断源高光。

接下来阅读 Linear、Tone 和 Color。

Linear

Linear 在非线性的 Tone 与 Color 阶段之前执行精确矩阵变换，为后续调色建立 合适的曝光和色彩平衡。

曝光与源白

Exposure 以档为单位；+1 会使场景线性 RGB 加倍。先设置合适的信号范围， 但不要用它抹去高光细节。源白 x、y 控件指定 Stage 1 适应的色度坐标。点击 Match White 可将源白恢复为 D65。

当前 Next 版本显示的 Working White 固定为 D65。Linear 还提供青红和黄蓝方向的 Balance、Spread 和 Heading。Balance 改变对立颜色的相对曝光；Spread 改变该方向相对白点的位移；Heading 在 xy 平面旋转方向。这些控件共同形成 Grade 矩阵。

校正白平衡时，选择在目标光照下拍摄的中性表面。调整源白直至该表面呈中性， 再检查其他颜色与肤色。若中性色正确而其他表面仍不协调，可使用 Balance、Spread 或 Heading 调整整体关系。它们作用于整幅图像，并非仅修改采样色块。

Blender 按 Image Texture 的 Color Space 设置解码图像。调色前请确认此设置； 错误的传递函数或色域无法靠 Grade 可靠补偿。节点会处理场景工作色彩空间适配； Next 支持 Linear Rec.709、Linear Rec.2020 和 ACEScg。

普通 Grade 在原生非线性阶段之前以精确矩阵计算 Stage 1。在 Grade Stack 中，完整的有序变换会一起采样。关于采样坐标与场景 RGB 的关系，见工作空间。

Tone

Tone 将中性输入亮度映射到感知明度曲线。完成 Linear 后，再设置输入锚点及 漫反射白和峰值参考。

设置影调锚点

Tone 提供以尼特为单位的 Black、Shadows、Midtones、White 和 Highlights 输入值。 Black 映射为黑色；Shadows、Midtones 和 White 分别映射到相应的中性明度锚点； Highlights 映射到已配置的峰值锚点。这些是柔和曲线锚点，不是硬截断，也不是 独立输出值。

根据图像安排这些输入值。SDR 图像的大部分影调可能位于漫反射白附近或以下。 对于 HDR，应区分漫反射表面与发光或镜面高光，不要把普通中间调推向最亮像素。 曲线 Fit 控制曲线接近控制点的程度，以及每个控制点影响相邻区域的范围。Peak 用于选择受支持的中性峰值目标之一。

共享 Grade 与 Stack 控件为静态。转换为 Node-Owned Grade 后，可为数值控件 制作动画，但离散的 Peak 选择除外。关键帧属于包含该节点树的 Action，并由该 节点树的所有用户共享。

检查曲线效果

在预期场景显示变换下检查 Grade 输出及最终图像。Tone 会改变 Color 接收的信号， 所以移动锚点后应重新检查选择性色彩调整。编辑 Stack 中选定的 Grade 时，可通过 Blender 的图像与 Viewer 显示比较效果。

Tone 模型介绍平滑插值及其参考明度刻度。

Color

Color 是 Stage 3，在 Linear 和 Tone 之后调整感知外观，并通过影调、彩度和色相 进行平滑控制。侧栏将数值控件分为 J、C、Adaptance 和 Warp。

J 与 C 响应

J 改变感知明度响应，C 改变彩度响应。每一类都具有四个影调锚点：Shadows、 Midtones、White 和 Highlights。每个锚点上的低／高彩度权重用于调整径向贡献， a/b 值用于调整对立色方向。Fit 控制影调间的平滑融合；Global C Gain 调整整体 彩度倍率。

建议先从较小的数值开始。J 可改变对比或突出主体；C 可增强或减弱色彩。调整时 同时检查中性色和高彩度颜色，因为较大的改动可能影响目标之外的颜色。

选择性 Adaptance

Adaptance 在 Shadows、Midtones、White 和 Highlights 处设置 a/b 目标坐标。其 彩度参数决定修正达到一半影响的位置。它用于在选定影调范围内改变外观，不是 Linear 的白平衡控件。

a、b 两个坐标共同表示一个径向目标。若请求超出有效范围，Next 会沿原方向缩短 该目标，使校准后的锥体响应保持有效，而不会分别截断 a 和 b。Limited 表示 当前采样请求（例如动画值）在求值时需要缩短。Shadows、Midtones、White、Highlights 的常用滑块范围依次为 ±4、±10、±20、±25，拖动增量为 0.01；键入值不会按此增量 取整。这些是编辑范围；有效的径向边界取决于影调 锚点。非有限数值请求会显示失败。

Warp 色网

Warp 在四个影调锚点各提供六个循环色相手柄：red、yellow、green、cyan、blue 和 magenta。彩度值是以档为单位的 log2 变化；色相值是存储的角度偏移；Scale 值也以档为单位，用于确定 H–K 修复之后使用的正缩放量。控件会沿循环色网及 影调锚点间插值。当前界面使用数值字段，不提供可拖动的图示。

相邻目标色相始终保留至少 4° 的循环间隔，包括 magenta 与 red 之间的接缝。 编辑时会固定当前色相，并在需要时沿任一方向推动相邻手柄。再次编辑发起色相时， 会一起求解其自动返回位置，在满足相邻间隔的前提下尽量返回保存的位置；暂时无法返回时， 该关系仍会保留。若手动编辑其中一个色相，会从其当前位置开始，并且只解除该色相 与先前自动调整的关系。

修改 Peak 会清除自动返回关系，并一起解析新的色相几何与 Adaptance 限制。 共享 Grade 的自动关系可跨帧保留；节点自有 Grade 则在实际帧或子帧改变时清除。 若插值后的动画值不满足色相间隔，求值会将角度投影到有效范围，并显示 Limited，不会改写保存的数值或关键帧。

修改 Warp 后应检查完整图像。求值使用 Tone 后冻结的选择器，然后依次执行 J/C 响应、Warp 色相／彩度并选择 Scale、选择性 Adaptance、H–K 修复，最后将 Scale 应用于修复后的对立色坐标，并将 Scale 的平方应用于带符号能量。该顺序符合参考模型的先守护、后缩放 约定。RGB 色域包含是独立的输出边界操作。

节点自有 Grade 的 Stage 3 数值可使用 Blender 关键帧。共享 Grade 和 Stack 条目 为静态。Stack 会将所有启用的正向 Grade 采样到单一的 33³ 预览，再细化为 65³ 最终变换；详见Grade Stack。

共享与动画 Grade

Grade 数据块保存权威的 Linear、Tone 和 Color 设置。着色器与合成器 Grade 节点可共用同一数据块，因此在任一编辑器中修改都会更新所有读取者。Grade Stack 拥有自己的有序条目列表，每个条目引用一个共享 Grade。

创建与复用 Grade

新建 Grade 节点尚未选择 Grade 数据块，显示默认值的控件会被禁用。编辑前，请用 选择器指定已有 Grade，或通过 新建调色 创建一个。选择相同数据块即可与其他 节点共享设置。已选择 Grade 时，新建调色会创建独立副本，适用于只有一个节点 需要不同设置的情况。重命名只会改变名称。

从节点解除 Grade 关联只会清除该节点的引用并恢复默认设置，不会删除数据块。Stack 条目可解除关联或移除，引用的 Grade 仍会保留。Blender 的伪用户设置可让未使用的 数据块在保存文件后继续存在。

为节点自有 Grade 制作动画

右键 Grade 节点并选择 转换为节点自有调色。Next 会把当前设置复制到节点上， 使其独立于共享 Grade。这种模式适合跟随 Blender 时间轴变化的变换。Linear、Tone 及 Stage 3 数值字段可使用 Blender 的普通关键帧命令或 Auto Key。离散的 Tone Peak 选择为静态设置。

动画属于所在着色器或合成器节点树的 Action。复用材质或节点组会让所有用户共享此 动画。要恢复共享设置，请选择 转换为数据块调色。Next 会根据当前帧值创建 Grade 数据块，并移除此节点的 Grade 动画；撤销可恢复之前的节点自有动画。

无论正向还是反向播放，如果当前帧的调色结果尚未就绪，节点自有 Grade 都可以 显示本次播放中最近完成的结果。Updating 表示显示的调色结果仍在追赶播放头。 停止播放或拖动时间轴后，节点会按所选帧的准确设置更新。

节点自有 Grade 不提供 Bake 控件，因为动画中的数值会随时间变化，并通过渲染预检 求值。共享 Grade 与 Grade Stack 支持 Bake，详见渲染与烘焙。

保存与渲染

扩展会在载入文件后以及渲染前协调内核。交互期间，准备替换结果时可暂时显示上一 个完整结果，并标记 Updating。只有当前的完整结果可用于渲染。若当前准备失败， 节点会显示保留 alpha 的洋红错误输出，渲染预检会停止受影响的帧。

场景工作空间

Next 的 Grade 参考白固定为 D65。Linear 面板以不可编辑的值显示 Working White: D65；当前产品版本不提供此项 Grade 设置。源白 xy 控件仍可用于 Stage 1 的创意校正。

节点会在场景 RGB 工作空间与内部调色坐标之间适配。支持的 Blender 场景空间为 Linear Rec.709、Linear Rec.2020 和 ACEScg。切换场景空间会更新外围转换 矩阵并协调派生节点图。不同空间下相同的 RGB 数字不代表相同颜色；若要保持色度学 等价，输入 RGB 也应由 Blender 正确转换。

普通 Grade 节点在原生 Tone／Color 节点图之前应用 Linear 矩阵。Grade Stack 在固定 的线性 ACEScg／ACES 白点坐标中采样完整序列，并在 LUT 两端转换场景坐标。LUT 采样白点 是实现边界，不会改变 Grade 固定的 D65 外观参考。

切换工作空间可能需要新的派生图数据。若准备或恢复失败，Next 会显示保留 alpha 的洋红错误结果，并阻止渲染，直到当前内核修复。LUT 坐标见求值与插值， 输入解码及 Stage 1 控件见 Linear。

Grade Stack

Grade Stack 将有序的共享 Grade 合并为一个采样变换。已启用的条目从上到下执行。 每个条目可选择正向（默认）或反向。反向条目可以出现在任意位置，也可以单独使用或连续排列。 反向求解会寻找一个输入，使 Grade 在 AP1-D65 边界映射之前的结果与目标匹配。RGB 和外观值均可作为目标。 调色可能会丢失信息，因此求得的输入可能是近似解，也可能只是多个解中的一个。反向条目的 Linear 变换必须可逆。

在反向 → 正向的相邻条目之间，如果两个条目的 Linear 变换相同，Stack 会直接传递求得的 Tone 之前的外观值。如果 Linear 变换不同，则在 CAT16 视锥空间中组合这两个变换。正向 → 反向 的相邻条目传递 Color 之后的外观值。两种交接都保留有符号的值，并避免经由 RGB 往返转换。 只有当序列以正向条目结束时，才会在输出端应用 AP1-D65 边界映射。如果序列以反向条目结束， 输出是求得的有符号 RGB 值，其中的分量可以超过 LUT 网格的上限 1024。

排列与编辑条目

使用 添加调色 创建已启用的空条目，再通过选择器指定共享 Grade，或用条目 中的加号按钮新建 Grade。使用条目控件可启用或旁路它、选定侧栏编辑目标、上下 移动或移除它。解除 Grade 关联会留下空条目；移除条目不会删除共享 Grade 数据块。 没有已启用 Grade 的 Stack 为恒等变换。

点击条目的编辑控件后，侧栏会显示该共享 Grade 的设置。修改会更新所有引用它的 普通 Grade 节点和 Stack 条目。若某一条目需要不同参数，请先创建独立 Grade。Stack 的成员关系和顺序属于节点；Grade 设置属于共享数据块。

整个序列共用一个 LUT

Stack 将所有已启用 Grade（包括每个 Linear 矩阵）计算到一个由 GPU helper 准备的 65³ LUT 中。编辑时可以先安装 33³ 预览，随后更新为最终 65³。预览采用最终网格 每隔一个顶点的坐标，GPU helper 分别计算两种分辨率。更新期间可暂时显示上一个 完整结果，但渲染和正常保存需等待当前的完整结果。

如果 LUT 包含超出容差的有限反向近似解，Stack 仍可使用该 LUT，并显示警告。警告会指出当前显示的 预览或完整 LUT 中有多少顶点受到影响，以及最大误差是容差的多少倍。

修改被引用的 Grade、条目方向、启用状态或顺序都会改变采样函数。安装结果前必须匹配 当前设置签名。文件载入后及渲染前，Next 会协调派生 LUT。若准备失败，会显示 错误，并以保留 alpha 的洋红结果关闭调色输出。

Stack 在固定的内部线性 ACEScg／ACES 白点坐标中运行。场景坐标转换位于 LUT 两端， 所有条目则包含在 LUT 内。详见场景工作空间和求值与插值。

渲染与烘焙

着色器和合成器中的共享 Grade 与 Grade Stack 节点提供 Bake 操作。节点自有的 动画 Grade 不提供 Bake，因为其设置会随时间变化。

烘焙节点输出

选中受支持的 Grade 或 Stack 节点，按当前路线设置输出尺寸，然后点击侧栏中的 Bake。结果会发布到受管理、打包的 32 位浮点 RGBA Image，节点随后改用该图像。 烘焙内容来自原生节点树求值：Grade 使用 helper 图像内核，Grade Stack 使用完整 65³ LUT 节点图。

Use Bake 可在图像输出和实时节点输出间切换，同时保留图像关联。调色设置、 被跟踪的源数据或渲染引擎发生更改后，仍可使用有效的烘焙图像。节点会提示烘焙 可能已过时，并说明原因。若其他输入仍匹配，切回烘焙时使用的渲染引擎即可清除 引擎变更提示。重新烘焙共享的受管理图像会更新所有读取节点。

设置跟踪包含目标节点、已启用 Stack 条目和实时上游 Grade／Stack 节点中的 Linear、 Tone 及全部 Stage 3 控件。

可选的 Shader Vector 输入只控制烘焙采样。未连接时，使用记录的烘焙 UV 图， Image 烘焙则使用当前活动渲染 UV 图。

Image 与 UV 路线

对于单个普通静态 Image、未连接源坐标的逐点 Shader 图，采用 Image 烘焙：每个源 纹素对应一个输出像素。无源图像的 Shader 常量会烘焙为 1×1 图像。合成器烘焙保留 原生输出范围；常量使用场景画布尺寸。

若图中有连接的坐标、依赖表面的着色、多个源 Image，或上游受管理的 UV 烘焙，则 需要在网格上执行 UV 烘焙。UV 烘焙使用 Cycles，并要求活动 UV 图位于 0–1 区域且 互不重叠。Image 烘焙遵从 Scene 渲染引擎：EEVEE 使用私有正交渲染；Cycles 使用 所选 CPU 或 GPU 设备；Workbench 或未知引擎会回退到 Cycles CPU。UV 烘焙使用 Scene 选定的 Cycles CPU／GPU。若 GPU 设备不可用，会显示失败，不会静默切换设备。烘焙 helper 不修改 Scene 或用户偏好设置。

烘焙会明确拒绝 UDIM／平铺图像、影片与图像序列、多视图／多层源、Shader to RGB、 影片剪辑与 Mask、关联或动画中的缓存／Alembic 几何、缺失或重叠的 UV，以及不受 支持的节点图实例。UV 烘焙前应应用不受支持的拓扑修改器或形变修改器。完整路线 边界见Next 烘焙策略。

渲染就绪

Next 会在渲染前协调派生内核。只有当前设置签名对应的完整结果可用于渲染。交互时 可暂时显示之前的完整结果并标记 Updating；当前结果准备失败时，会显示保留 alpha 的洋红输出，并阻止渲染预检。Grade Stack 编辑时可先使用 33³ 预览，但最终 渲染需等待 65³。
