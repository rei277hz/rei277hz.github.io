简介

持续维护的手册： 本出版物旨在跟进 Perceptual Grade 的最新版本。 用户手册描述的是 1.23.2 界面与工作流程；相关操作说明、宿主录像和 许多运行时工程内容仍落后于当前参考模型。下载与测量保留其原始版本 和范围。各章会注明所描述的产品或模型。

Perceptual Grade 将白平衡、自定义影调曲线与选择性色彩调整串成三个阶段。 Blender 实现提供用于着色与合成的节点；保留的 DCTL 运行于 DaVinci Resolve。 它们可用的控件与阶段 3 策略和最新参考模型有所不同，复现调色时请确认所用 实现的版本与范围。

在着色器中连接材质

Image 或 Render Layers → Perceptual Grade → 输出，另接 Viewer 分支。

在 DCTL 两侧显式放置 CST

使用不启用自动色彩管理的 DaVinci YRGB 项目，并添加三个串行节点。

第一个节点放置输入 Color Space Transform。Input Color Space 与 Input Gamma 应匹配素材，Output Color Space 设为 CIE XYZ，Output Gamma 设为 Linear。

第二个节点放置 Perceptual Grade。它接收并输出线性 XYZ；Destination White 应设为该信号所表示的白点。

第三个节点放置输出 Color Space Transform。Input Color Space 设为 CIE XYZ、Input Gamma 设为 Linear，再选择用于监看或交付的输出空间与伽马。

对于 D65 链路，例如转换为 XYZ 的 Rec.709 SDR 或 Rec.2020 PQ 素材，使用 Destination White = D65，并在输出 CST 中保持一致。ACES 白点的 XYZ 链路使用 ACES；明确采用日光 D60 的链路选择 D60 daylight，其坐标与 ACES 白点不同。XYZ 本身不指定白点，应匹配实际转换，而不是依据相机名称或画面的偏色。Source White 才是用于消除偏色的调色控件。

图示 D65 链路的两个 CST 都关闭 Use White Point Adaptation，以保留该白点。如果有意适应到另一白点，则应把 Destination White 设为适应后信号的白点。XYZ 中的 D65 中性色满足 、；开始调色前可用中性色块检查转换。

输入 CST、DCTL 的 Destination White 和输出 CST，以及完整的三节点链路。

设置调色链路时，关闭转换 CST 的自动影调映射、色域映射、Apply Forward OOTF 和 Apply Inverse OOTF。HDR 转 SDR 监看应在下游有意设置显示变换。检查线性信号的尺度：DCTL 把 视为 Reference Nits。如果转换按另一亮度归一化，应在 DCTL 前显式缩放，并在其后做相反调整。

分三个阶段调色

用同一套流程处理两张图像。示例 A 是 SDR，示例 B 是 HDR；它们在本书中始终分别位于左侧和右侧。每组示例都展示同一个控件，但调色意图不同。

先让两张图像的光照恢复中性，并平衡曝光。细调 SDR 图像较柔和的色彩关系，同时保留 HDR 图像中漫反射表面与明亮高光之间的层次。在 Tone 中，为 A 建立 S 形反差曲线，并用类似伽马的曲线提亮 B 的暗部。将这些调整带入 Color，再用相同控件配合每张图像自己的影调分布进行细调。

每段演示都从上一段演示的结果继续。整个流程中保持图像、裁切、视图变换和曝光设置不变；六项 Color 操作都应保留已完成的 Linear 与 Tone 调整。并排动画比较的是两个独立示例，而不是前后对比画面。

在 Linear 中，让应该为白色的部分真正显示为白色，再对照色卡检查曝光与色彩关系。在 Tone 中塑造反差并提亮阴影，然后比较 SDR 与 HDR 波形。在 Color 中，按所选色调区域调整明度、彩度、Adaptance 与色相。

线性

保留版本： 本使用章节及截图描述 1.23.2，仍滞后于最新模型。当前参考见理解模型；这些控件并非 Next 未来的 Warp 实现。

线性校正为图像的创意调色建立可靠起点。它修正整幅图像的光照偏色与整体色彩关系，让 Tone 和 Color 可以塑造观感，而不必补偿不需要的色偏。Global Exposure 提高或降低整体亮度；先建立合适的亮度，再依次处理白平衡与下面的色彩关系。

平衡白点与色彩关系

Source White 就是常见的白平衡调整：让应该呈现为白色的区域真正显示为白色。寻找在预期光照下应当中性的表面，例如白纸、灰卡或色卡的中性色块。结合表面本身与示波器轨迹判断；有色物体不是白点参考。

在每个示例中，先拖动扩展的 Linear 矢量示波器，直到中性表面不再有不需要的偏色。将 Source White 重置到起始位置，再直接拖动源白点，重复完成校正。这是同一种调整的两种操作方式。保留第二次校正的结果，继续下一段演示。

在 Resolve 中，将 Perceptual Grade DCTL 的 Source White 设为 Custom xy，再调整 Source White x 和 Source White y。这两个滑块可以重现任一种拖动操作。Destination White 保持为 CST 设置所确定的值。

Balance 在保持已确定白点不变的同时，改变相对颜色的亮度关系。增加 Cyan-Red Balance 会让青色相对红色更亮；增加 Yellow-Blue Balance 会让黄色相对蓝色更亮。当中性表面已经正确，而某一组颜色的一侧显得过亮或过重时，这类调整很有用。

Spread 和 Heading 以另一种方式改变这些关系。更宽的 Spread 通常让该方向的颜色更饱和；更窄的 Spread 则让它们趋近白色。Heading 旋转方向，从而改变色相。全部六个控件都会保持已确定的白点，所以这些调整不会撤销白平衡。

接着第一段演示，使用两个 Balance 手柄、两个 Spread 手柄和两个 Heading 手柄。在 A 中，平衡相对颜色的亮度，扩展偏灰的色彩关系并细调色相；在 B 中，平衡另一组亮度关系，收敛较强的色彩并细调色相。每次改变一种关系时，都要观察完整图像。

DCTL 中对应的六个滑块为 Cyan-Red Balance、Yellow-Blue Balance、Cyan-Red Spread、Yellow-Blue Spread、Cyan-Red Heading 和 Yellow-Blue Heading。

示例：匹配拍摄到的 ColorChecker

接着 Linear 调整继续操作。使用在待校正光照下拍摄的 ColorChecker，并以 ColorChecker2014 EXR 为参考。参考图像采用 ACEScg，请在其 Image Texture 或 Image 节点上显式设置该色彩空间；同时正确设置照片自身的输入编码。

将照片连接到 Color，将 EXR 的 Color/Image 输出连接到 Color Reference。裁切并旋转拍摄的色卡，使其与 EXR 的构图一致，并尽可能减少背景。调色作用于 Color；Color Reference 提供独立的对照轨迹。

照片与 ACEScg EXR 图像节点、两条连接，以及显示参考轨迹的 Linear 矢量示波器。

先比较中性色块。细调 Source White 和 Global Exposure，再使用 Balance、Spread 和 Heading 手柄，让彩色色块的读数靠近参考值。同时观察多个色块：单一全局矩阵是一种折中，光照、眩光和相机渲染都可能使精确匹配无法实现。将得到的校正结果带入 Tone。

在 Linear 中，红色参考轨迹绘制在主轨迹上方。单击示波器或 Tone 曲线的空白区域，会切换所有阶段的参考显示；拖动 Linear 矢量示波器则调整源白点。单击与拖动各有不同用途。

在 Tone 中，参考显示于 After 波形和曲线直方图。在 Color 中，波形与矢量示波器会显示所选输入色调区域的对应位置。各直方图高度分别归一化，因此它们的高度并不能用于测量曝光。

扩展的波形测量感知明度，而矢量示波器显示显示端 Rec.709 信号彩度。Resolve 的原生示波器使用其所选宿主刻度。在 Resolve 中，应让照片与参考经过相同的 CST 和显示处理链进行比较，再使用上述同名 Linear 滑块；DCTL 没有扩展中的 Color Reference 插口。

示波器采样支持平面图像、Render Layers 的色彩通道、RGB 常量、转接节点和 Perceptual Grade 链。使用 Render Layers 时请先渲染；程序化节点网络无法采样时，请使用烘焙图像。

影调

保留版本： 本使用章节及截图描述 1.23.2，仍滞后于最新模型。当前参考见理解模型；这些控件并非 Next 未来的 Warp 实现。

保留 A 和 B 中完成的 Linear 调整。现在根据各自的目标塑造影调关系：A 增强反差，B 提高暗部的可读性。

塑造反差并提亮阴影

用相同的 Tone 地标实现不同目的。在 A 中压低较暗的影调并提亮较亮的影调，形成 S 形反差曲线。在 B 中将暗部和中间区域提亮，形成类似伽马的曲线，同时让白色和最亮高光尽量保持原有关系。

拖动 Before 波形上的地标，或沿水平方向移动它的曲线圆点，以确定应映射到该地标目标的输入影调。After 波形显示结果。将输入地标向右移，表示希望较高的输入亮度达到同一目标；向左移则表示希望较低的输入亮度达到该目标。曲线会平滑融合这些调整要求。

在 Resolve 中，Perceptual Grade DCTL 使用 Input Black Nits、Input Shadows Nits、Input Midtones Nits、Input White Nits 和 Input Highlights Nits 这五个地标。Remap Fit 改变曲线拟合方式。Reference Nits 设置漫反射白的校准值，Peak Anchor Nits 设置亮部锚点。

这些 Nits 输入描述的是具有指定明度的中性色。应查看生成的曲线与波形，不要期待曲线在每个地标上都被硬性固定。放置各亮度后，调整 Remap Fit，让过渡范围更宽，或更集中在地标附近。

在波形上比较 SDR 与 HDR

在示例 A 中，寻找暗部、中间调以及像纸张这样的漫反射白。SDR 图像通常会将这些区域聚集在参考白线下方或附近，亮部细节可能只占据参考白附近的一小段范围。

在示例 B 中，找到类似的漫反射表面，再观察更亮的光源、窗户或镜面反射。HDR 波形可以把亮部特征放在远高于漫反射白的位置，同时让表面和中间调保持较低。分别比较这些区域；最高亮度峰值不代表图像的平均影调。

A 显示 SDR 图像及其紧凑的影调范围；B 显示 HDR 图像、漫反射白与明显分离的亮部高光。请使用相同的波形刻度，并标出这些特征。

参考白线为 ，也就是明度读数中的 。默认 Reference Nits 为 203，因此该线代表 203 尼特的中性白。即使当前 Grade 使用较低的 Peak Anchor Nits，图表仍会延伸到 4000 尼特中性的明度。扩展的感知波形使用这一明度刻度；Resolve 的原生示波器则使用 Resolve 中选定的刻度。

这个共用刻度解释了为什么 A 中会有空余的高亮余量。不要为了填满它而抬高中间调。在 B 中，应让漫反射白与真正明亮的区域保持有用的间隔，而不要把最亮峰值当作普通白色。

色彩

保留版本： 本使用章节及截图描述 1.23.2，仍滞后于最新模型。当前参考见理解模型；这些控件并非 Next 未来的 Warp 实现。

保留 Linear 和 Tone 的调整结果。以下操作在两个示例中都接着前一步继续进行，不要在录像之间重置。A 始终为 SDR，B 始终为 HDR。在 Resolve 中，请使用每段演示旁列出的 Perceptual Grade DCTL 滑块。

点击曲线上的圆点、S/M/W/H 标签或波形指示线来选择色调区域。曲线高度表示调整强度，并不是最终像素值。Cₗ 侧重低彩度颜色，Cₕ 侧重高彩度颜色，两者都采用平滑权重。示波器显示所选输入色调区域经过调色后的结果。

明度 J 曲线：每张图像调整两个色调区域

选择 Lightness J 和 Cₗ 曲线。在 A 中提亮 Shadows，并让 White 稍微更突出；在 B 中提亮 Midtones，同时收敛 Highlights。两张图像都用同一种手柄调整两个色调区域，以实现不同目的。

DCTL 滑块：A 使用 Shadows Cₗ → J 和 White Cₗ → J；B 使用 Midtones Cₗ → J 和 Highlights Cₗ → J。处理高彩度颜色时，改用对应的 Cₕ → J 滑块。Lightness Fit 控制各色调系数融合的范围。

明度 J 与彩度 C 曲线：共用一个色调区域

在两个示例中都选择 Midtones。先调整 Cₗ → J 曲线，再切换到 Chroma C，保持色调选择不变并调整 Cₗ → C。A 可以提亮偏灰的主体并增加色彩；B 可以压低过于突出的中间调并减弱其色彩。这两类接收通道共同作用于同一个色调区域。

DCTL 滑块：Midtones Cₗ → J 和 Midtones Cₗ → C。对应的高彩度控件为 Midtones Cₕ → J 和 Midtones Cₕ → C。彩度贡献获得完整权重时，+1 使 C 加倍，−1 使其减半。Chroma Fit 塑造调整在色调上的影响范围；Global C Gain 则改变所有色调区域的彩度。

明度 J 与彩度 C 的 a/b 平面：共用一个色调区域

在两张图像中都保持 Midtones 选中。在 Lightness J 平面中移动手柄，提高一个色相方向的明度，同时降低其相反方向。切换到 Chroma C，沿同一方向调整色彩强度。A 可以让主体从背景中更突出；B 可以削弱干扰色，同时保留主体。这是在每张图像的同一色调区域上配合使用 J 和 C 调整。

DCTL 滑块：Midtones a → J、Midtones b → J、Midtones a → C 和 Midtones b → C。沿对角线移动会组合 a 与 b 的作用。扩展的平面中，+a 向上，+b 向左，与其矢量示波器的方向一致。

Adaptance 平面：每张图像调整两个色调区域

选择 Adaptance。在 A 中减轻 Shadows 的偏色，再细调 White；在 B 中校正 Midtones，再细调 Highlights。移动各色调区域的手柄时，观察该区域内应接近中性的表面。

在 DCTL 中，A 使用 Shadows Adaptance a、Shadows Adaptance b、White Adaptance a 和 White Adaptance b。B 使用 Midtones Adaptance a、Midtones Adaptance b、Highlights Adaptance a 和 Highlights Adaptance b。

Adaptance Strength 控制调整量和彩度保护；Adaptance Fit 控制色调间的融合。平面上的均值十字与置信范围描述采样到的近中性像素，并放大 5×，便于看清细微偏色。

色相集中平面：每张图像调整两个色调区域

选择 Hue，并使用其 a/b concentration 平面。在 A 中，先收拢 Shadows 中分散且干扰画面的色相，再细调 White；在 B 中，先收拢 Midtones 的色相，再细调 Highlights。Concentration 会将色相拉向所选方向，并扩大相反一侧色相间的距离。

DCTL 滑块：A 使用 Shadows Hue Concentration a、Shadows Hue Concentration b、White Hue Concentration a 和 White Hue Concentration b。B 使用 Midtones Hue Concentration a、Midtones Hue Concentration b、Highlights Hue Concentration a 和 Highlights Hue Concentration b。

色相旋转：每张图像调整两个色调区域

使用 Hue rotation 曲线，让同一色调区域内的颜色一起旋转。在 A 中，将 Shadows 和 White 分别引向不同的配色；在 B 中，独立调整 Midtones 和 Highlights。Rotation 旋转整个色相环，而前面的 Concentration 操作改变环上的色相间距。

DCTL 滑块：A 使用 Shadows Hue 和 White Hue；B 使用 Midtones Hue 和 Highlights Hue。Hue Fit 控制 Rotation 与 Concentration 在色调区域间的融合。每次调整后都应保留前面的工作，并重新观察完整图像。

尝试范围更广的创意调色

自行试用 Global Cₗ → Hue 和 Global Cₕ → Hue。它们用平滑权重旋转所有色调区域中的低彩度和高彩度颜色。将其与各色调区域的控件组合，可以探索更具风格的配色。

创建独立变化

选择某个 Grade 后点击“新建 Grade”，会以当前参数创建独立副本并分配唯一名称。之后的修改影响副本的用户。

例如，两个材质和一个合成节点共同使用“暖色场景”。从任意一个节点调整曝光都会更新三者。需要单独压暗某个材质时，在其节点上创建 Grade 副本，将其重命名为“暖色场景－较暗”，再调整曝光。

直接复制节点或材质仍然共享 Grade。堆栈的铅笔也编辑共享 Grade；创建独立堆栈不会自动复制其引用的 Grade。

重命名、解除关联与保留

选择工作白点

保留版本： 本使用章节及截图描述 1.23.2，仍滞后于最新模型。当前参考见理解模型；这些控件并非 Next 未来的 Warp 实现。

工作白点属于共享 Grade，始终默认为 D65，ACEScg 项目也一样。切换 Blender 工作空间不会改变这个选择。请在侧栏的阶段 1修改；堆栈需先点击已启用条目的铅笔。修改会更新该 Grade 的所有用户。

预设与 DCTL 一致：D65、D60 日光、ACES、D50、D55、D75、DCI 白点、等能量 E。Blender 不提供自定义 xy。ACES 白点与 D60 日光的坐标略有不同，因此分别列出。

白点表示什么

外观模型的参考白点描述调色使用的适应环境。它与存储场景的 RGB 原色、最终显示器的白点是不同的概念。D65 提供跨项目一致的默认调色环境；扩展不会根据显示器、视图变换或场景色域自动推断此设置。

例如，ACEScg 场景使用 D65 Grade 时，扩展先把场景 RGB 转为 XYZ，再通过 Bradford 将 ACES 白点适应到 D65，随后执行三个调色阶段。最后适应回 ACES 白点并输出 ACEScg RGB。这样，等通道场景中性灰进入外观模型时也是 D65 中性灰，不会成为“以 D65 为参考观看的未适应 ACES 白点刺激”。

节点仍在 Blender 视图变换之前处理场景线性数据。选择 D65 不会把调色移动到色调映射之后，也不会使它成为显示参考调色，更不会覆盖 ACES 输出变换的创意白点或显示编码。显示器白点本身不能决定所有上游外观模型操作的白点；ACES 也分别定义创意白点和显示编码。

使用默认 D65 可获得一致的调色环境，也可以有意识地选择其他预设。请通过最终采用的视图变换与显示配置判断效果。

LUT、堆栈与保存

固定的内部线性 RGB 基底使 LUT 采样网格独立于场景色域。普通节点将阶段 1 放在非线性 LUT 之外；堆栈在烘焙单个 LUT（33³ 预览、65³ 最终质量）前，按解析路径计算各 Grade 的全部阶段及白点衔接。最外侧的场景坐标矩阵不是额外的调色阶段或 LUT。

修改 Grade 白点会自动触发相关 LUT 重烘焙；仅切换 Blender 工作空间时更新两端矩阵并复用调色 LUT。Alpha 保持不变，RGB 转换不会裁剪负值。

保存的原生节点图可以在禁用扩展时保持已保存的外观。实时编辑、动画更新，以及工作空间切换后的图更新，需要启用扩展。

DCTL 保留自己的目标白点行为，切换该设置不会自动转换已保存的校正矩阵。

烘焙 LUT 自己使用什么白点？

烘焙与示波器更新

每个堆栈每次使用一个 LUT：交互预览为 33³，编辑稳定后为 65³，包含所有已启用条目的全部三个阶段，包括每个线性矩阵。烘焙器在最终网格顶点直接计算整个序列的正向方程和尽力反解，不串联已有的 Grade LUT。

修改引用的 Grade、启用状态、方向或顺序，会自动安排预览和最终细化。仅重命名不会改变变换或 LUT。线性阶段也位于堆栈 LUT 内，因此线性编辑同样触发烘焙。烘焙期间使用 Bradford 连接各 Grade 白点；LUT 的边界仍固定为线性 原生 ACEScg／ACES 白点，场景坐标适配矩阵位于 LUT 外。

示波器只使用当前已安装的 LUT。 33³ 预览同时更新原生节点输出和示波器。手柄、曲线立即更新；状态文字标明正在显示 33³ 预览并等待 65³ 细化。没有额外的解析采样图像预览。

首次预览在 40 ms 后可开始。连续拖动时，正在计算的 33³ 参数快照会完成并显示，期间的新修改合并为一个最新请求；因此预览可能短暂落后于手柄，但持续移动不会一直取消预览。距上次编辑至少 300 ms，且匹配的预览已经完成后，才开始 65³ 细化。这些时间是调度阈值，不是烘焙耗时保证。新预览准备好之前保留上一个已安装结果。

33 点坐标轴取自 65 点坐标轴的每隔一个顶点。全部 35,937 个预览顶点原样复用，细化仅计算其余 238,688 个顶点。对于同一参数快照，总解析计算量仍为 274,625 个顶点，不从粗网格插值生成最终顶点。预览每轴有 32 个正侧单元，保持相同的原生 ACEScg／ACES 白点坐标、0…1024 边界及普通 log1p κ = 0.01 曲线。网格之外的输入取最近边缘单元而不做外推；边界规则见直接求值与采样求值。

首次预览完成前节点直通，示波器等待。预览和最终 LUT 安装时都会刷新示波器；二者使用不同的缓存标识与紧凑图集尺寸。过期的最终结果不能发布。即使已安装预览，最终渲染准备及正常保存仍等待最新参数的 65³ 结果。普通 Grade 节点的渲染方法行为不变。

反向烘焙会自动优先使用可用的 Blender 计算着色器，Python／NumPy 为 CPU 回退路径。 每个 GPU 顶点计算整个序列，不查询中间 Grade 表。设备标记的反向顶点在安装前通过 完整 float64 CPU 序列重新求值。侧栏显示所选后端和回退原因。已发布的匹配 GPU 预览 在细化改用 CPU 时保留公共顶点。前台保存／渲染回调没有保证的绘图上下文，因此待完成 的表使用 CPU 完成；已完成且匹配参数的 GPU 表不必重新烘焙。

黑点裁剪、奇异矩阵、负值分支和强色彩折叠可能丢失信息或产生多个原像，因此反向为 尽力求解。奇异矩阵使用 CPU 伪逆；CPU 诊断记录复现误差和奇异矩阵数量，GPU 诊断记录 float32 策略、RGB 搜索及修复顶点。GPU 诊断不代表未标记顶点满足更严格的 CPU 残差容差。 网格之间的插值仍有独立误差。参见自动 GPU 烘焙。

保存与共享

正常保存会打包最终 LUT 和原生计算图。关闭扩展后仍可渲染已保存外观；编辑、自动重新烘焙和动画更新需要扩展。着色与合成编辑器使用相同的共享 Grade 和堆栈行为。

参见渲染方法、工作白点、求值与插值及正向／反向数学规范。

渲染方法

保留版本： 本使用章节及截图描述 1.23.2，仍滞后于最新模型。当前参考见理解模型；这些控件并非 Next 未来的 Warp 实现。

普通 Grade（调色） 节点始终正向应用 Grade。在 Perceptual Grade 侧栏选择 Baked LUT（烘焙 LUT） 或 Direct（直接求值）。节点本体显示 Grade 选择器和用于显示／隐藏图表的铅笔，不显示渲染方法或方向下拉框。Resolve 中的 Perceptual Grade DCTL 直接计算解析方程。

根据用途选择

着色通常可先选择烘焙 LUT：材质在多次采样与光线反弹中复用预计算结果。合成通常可先选择直接求值：原生节点计算模型，避免整幅渐变上的有限三维网格误差。

普通节点的 LUT 存储影调与色彩变换，线性矩阵保持在 LUT 外。直接求值使用平滑的一维系数表计算外观与色彩操作。对于强调整或困难渐变，应比较两种方法后选择最终渲染设置。

渲染方法属于节点。同一个 Grade 可以被不同渲染方法的节点共享。工作白点属于 Grade，只在阶段 1 的侧栏中显示。

编辑期间

普通调色节点选择烘焙 LUT 时，在准备新表期间暂时采用直接求值；匹配的新表完成后接管输出。最终渲染等待当前表完成。直接求值节点始终保持直接求值。

自动 GPU 烘焙

从 1.23.0 起，非线性 LUT 烘焙会自动使用通过启动着色器检查的 Blender 图形设备， 包括普通 Grade 的正向 LUT 和正向／反向 Grade Stack。渲染方式仍是“烘焙 LUT”； GPU 或 CPU 指的是生成这张表的方法。

侧栏显示“烘焙：GPU”及实际图形后端／设备，或“烘焙：CPU”及回退原因。 选择依据是 Blender 图形上下文，与 Cycles 的 CPU／Metal／CUDA 设置、合成器渲染设备无关。 仅含矩阵的变换不需要非线性求解，继续使用 CPU；软件图形设备、缺少上下文、着色器 检查失败和奇异反向矩阵也回退 CPU。

着色器源代码由 Blender 自身 GPU API 编译。第一次使用可能等待驱动编译，随后编辑复用 同一程序。温态计算分成有限批次；设备标记的反向顶点在发布前通过完整 CPU 变换重新 求值。GPU 使用 float32，CPU 使用 float64，反向容差不同，因此 GPU 表有独立诊断， 不保证与 CPU 顶点逐位相同。参见验证与工作站测量。

GPU 计算在绘图上下文运行。如果保存或渲染要求的表尚未完成，会用 CPU 完成； 已经安装且匹配参数的 GPU 表直接复用。扩展不需要额外 GPU 包或预编译扩展二进制。

GPU 启动错误与日志

“正在准备 GPU 烘焙”表示任务等待绘图上下文中的 GPU 启动。 1.23.2 在向量列上完成反向着色器的整个 Broyden 更新，避免日志中 Metal 编译器 不支持的 outerProduct 内建函数和矩阵／标量除法。 编译或计算失败会转 CPU，侧栏保留异常类型／消息，控制台为每个图形上下文 输出一次警告及完整调用栈。禁用后重新启用扩展，或重新启动 Blender，才会重试失败的上下文。

扩展没有单独的日志文件。在 macOS 上保存项目并退出 Blender，然后从 Terminal 启动：

/Applications/Blender.app/Contents/MacOS/Blender --debug-gpu \
  2>&1 | tee "$HOME/Desktop/perceptual-grade-gpu.log"

若安装位置不同，请调整应用路径。复现烘焙后，终端输出也会保存为桌面上的 perceptual-grade-gpu.log。物理 Metal 编译与性能仍需在 Mac 上验证； 软件 OpenGL 算术测试不能替代这项检查。

调色堆栈

Grade Stack（调色堆栈） 每次使用一个 LUT，编辑预览为 33³，最终质量为 65³，包含整个已启用序列及每个线性矩阵。各条目有正向／反向开关。只需一个反向 Grade 时，使用单条目的反向堆栈。

堆栈先安装 33³ LUT，快速更新节点输出和示波器；编辑稳定后复用所有预览顶点，细化至 65³。连续修改合并为后续预览请求。示波器与原生节点输出始终使用同一已安装 LUT。最终渲染及正常保存要求最新参数的 65³ 结果。首个预览完成前节点直通，示波器等待。调度与精度细节见堆栈指南。

参见反向调色与调色堆栈、求值与插值和渲染方法测量。
